# 005 認証：Better Auth

## 決めたこと

ログインの仕組みは、Better Auth を使って作る。

- ログインIDとパスワードでログインする（メールアドレスは使わない）
- 管理者・指導担当者・ゲストの3つの役割で、できることを分ける
- ゲストは、登録しなくても架空のデータで使える

## 比べた候補

| 候補 | このアプリで使うとどうなるか |
| --- | --- |
| 自分で全部作る | パスワードの暗号化などを、自分で書く必要がある。まちがえると、安全性に直接ひびく |
| 外部のログインサービス（Clerk、Amazon Cognito など） | ログインの仕組みを外のサービスに任せられる。ただし、担当者の情報が外のサービスに置かれ、料金や設定の手間もかかる |
| Googleでログイン | パスワードを管理しなくてよい。ただし、職場で個人のGoogleアカウントを使えるとは限らず、メールアドレスなどの情報もアプリに渡される |
| Auth.js（NextAuth.js） | 長く使われてきた。ただし、2025年9月から Better Auth のチームが管理していて、新しいプロジェクトには Better Auth がすすめられている |
| **Better Auth（選んだもの）** | ログインIDでのログイン、役割の管理、ゲストのログインが、それぞれ用意されている。Prisma と PostgreSQL で使える |

## 選んだ理由

- このアプリに必要な3つ（ログインIDでのログイン、役割分け、ゲスト）が、すべて用意されている
- ゲストのログインでは、メールアドレスやパスワードなどの個人情報を入れずに使える。「必要なデータだけを持つ」という方針に合う
- パスワードの暗号化など、安全性に関わる部分を自分で書かなくてよい

## あきらめたこと（トレードオフ）

- Better Auth のやり方に合わせる必要があり、ログインの細かい動きを自由に変えにくい
