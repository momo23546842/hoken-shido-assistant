# 002 フレームワーク：Next.js

## 決めたこと

画面とサーバー（API）を、Next.js の1つのプロジェクトで作る。サーバーの処理は Route Handlers で書く。

## 比べた候補

| 候補 | この組み合わせで作るとどうなるか |
| --- | --- |
| React（画面）＋ Express（サーバー） | 画面とサーバーを別々のプロジェクトとして作り、別々に公開する。設定や公開の作業が2倍になる |
| React（画面）＋ Python の FastAPI（サーバー） | サーバー側でPythonのAIライブラリを使える。ただし、言語が2つになり、001の理由（同じ言語で書く）と合わない |
| **Next.js（選んだもの）** | 画面とサーバーを1つのプロジェクトで作り、まとめて公開できる |

## 選んだ理由

- 1人で作るので、画面とサーバーを1つのプロジェクトで管理できるほうが、作業も公開も簡単になる
- AIのAPIキーを、サーバー側（Route Handlers）だけで使える。ブラウザにAPIキーが出ないので、安全に AI を呼び出せる
- インターンシップで使った経験がある

## あきらめたこと（トレードオフ）

- Next.js は、画面をサーバーで作るかブラウザで作るか、などの決まりごとが多く、覚えることが多い
- Next.js を作っている会社のサービス（Vercel）で公開するのが一番簡単だが、今回は AWS で公開するので、公開の設定に少し手間がかかる
