# 004 AI：Groq とローカルLLM

## 決めたこと

- AIは「メモの整理」と「SOAPの下書き」の2つだけに使う。カロリーなどの数値は、AIに作らせない
- デモ（架空のデータ）では Groq を使う。実在の人のデータを扱う場合は、ローカルLLMを使う想定にする
- どのモデルを使うかは、#9 の技術検証の結果で決める

## 比べた候補

| 候補 | このアプリで使うとどうなるか |
| --- | --- |
| AIを使わない（決まったルールだけで読み取る） | 「茶碗1杯」「おかわり」「半分残した」など、メモの書き方がさまざまなので、ルールだけでは読み取りきれない |
| 有料のAIのAPI | 精度は高いが、使った分だけ費用がかかる。データは外部のサービスに送られる |
| **Groq（デモで選んだもの）** | 無料枠があり、返事が速い。データは外部のサービスに送られるので、デモでは架空のデータだけを使う |
| **ローカルLLM（実在のデータで選んだもの）** | 自分のパソコンやサーバーの中で動くので、データを外に出さない。ただし、動かすパソコンやサーバーの性能が必要で、精度は確かめる必要がある |

## 選んだ理由

- 書き方がさまざまな面談メモを読み取るには、AIが向いている
- 費用をかけずに作るため、デモは無料枠のある Groq にした
- 実在の人の健康の情報は外に出したくないので、AIを呼び出す部分を1か所（`lib/ai/`）にまとめ、ローカルLLMに切りかえられる作りにする
- AIは、もっともらしい間違いを作ることがあるので、数値はAIに作らせず、計算のルール（rules.md）で出す
- AIの読み取りがどれくらい正しいかは、評価用データを使って数字で測る（#9）

## あきらめたこと（トレードオフ）

- 無料枠には回数の上限があり、たくさん使うと止まる
- 有料のAIより精度が低い可能性がある。評価用データで確かめて、足りなければプロンプト（AIへの指示）や、担当者が直せる画面で補う

## 今後に向けて

- このアプリは、氏名など個人を特定できる情報を入れない作りにしている。それでも、メモには体重や食生活などの健康の情報が入るので、実在の人のデータを扱うときは、ローカルLLMを使う
- 今後、個人情報が入っている今の業務システムと連携する場合は、AIに送るデータに個人情報がまざる可能性が高くなる。そのため、データを外に出さないローカルLLMを使うことを前提にする
