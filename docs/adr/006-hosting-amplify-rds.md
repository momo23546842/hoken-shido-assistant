# 006 公開先：AWS Amplify Hosting と Amazon RDS

## 決めたこと

- アプリは AWS Amplify Hosting で公開する。GitHub の main にマージすると、自動で公開される
- データベースは Amazon RDS の PostgreSQL を使う
- Next.js の最新版は16。AWSの公式の資料では、Amplify Hosting の対応は15までと書かれているが、15は安全の修正を受けられる期間が終わる時期に来ているため、16を使う。Week 3 で、まず小さなアプリで Amplify で動くかを確かめ、動かない場合は公開先を見直す

## 比べた候補

| 候補 | このアプリで使うとどうなるか |
| --- | --- |
| AWS App Runner | 2026年4月30日から新しい利用者を受け付けていないので、使えない |
| ECS Express Mode ＋ RDS | アプリを「コンテナ」にまとめて動かす。設定が多く、1人で作るには手間がかかる |
| EC2 または Lightsail（サーバー1台） | 費用はおさえやすいが、サーバーの安全対策（OSの更新など）を自分で続ける必要がある |
| Vercel ＋ 外部のデータベース | 一番簡単に公開できるが、AWSではなくなる |
| **Amplify Hosting ＋ RDS（選んだもの）** | Next.js をそのまま公開でき、GitHubと連携して自動で公開される |

## 選んだ理由

- 1人で作るので、公開の作業を簡単にして、アプリの中身に時間を使いたい
- GitHub の main にマージすると自動で公開されるので、今のプルリクエストの流れとそのままつながる
- サーバーの安全対策（OSの更新など）を AWS に任せられる

## あきらめたこと（トレードオフ）

- Amplify Hosting は、新しい Next.js への対応が遅れることがある。そのため、公式の資料に書かれていない Next.js 16 が動くかを、自分で確かめる必要がある
- コンテナやサーバーを自分で動かす経験は、この構成では得られない
