# 001 言語：TypeScript

## 決めたこと

画面もサーバーも、TypeScript で書く。

## 比べた候補

| 言語 | この言語で作るとどうなるか |
| --- | --- |
| JavaScript | 型がないため、データの形のまちがいは、動かしてみるまでわからない。たとえば、画面から受け取ったカロリーが文字の「80」のままだと、`"80" + 10` が 90 ではなく「8010」になってしまう。こうしたまちがいに、動かす前には気づけない |
| Python | 型ヒントと Pydantic を使えば、データの形を確かめられる。AIのライブラリも多い。ただし、画面は JavaScript か TypeScript で作る必要があるので、言語が2つになる |
| **TypeScript（選んだもの）** | 型があるので、データの形のまちがいを動かす前に見つけられる。画面もサーバーも同じ言語で書ける |

## 選んだ理由

- カロリーや体重のような数値を扱うアプリなので、データの形のまちがいを、動かす前に見つけたい。まちがった数値で、対象者に誤った説明をしないため
- AIの出力も、型と Zod で確かめてから使える
- インターンシップで Next.js と一緒に使った経験がある

## あきらめたこと（トレードオフ）

- AIやデータ分析のライブラリは、Python のほうが多い。このアプリは画面が中心で、AIはAPIで呼び出すだけなので、TypeScript でも足りると判断した
